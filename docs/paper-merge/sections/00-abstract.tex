\begin{abstract}
Merging RDF serializations creates ordering conflicts and misses semantic ones.
We describe and evaluate a three-way merge in which the schema defines a
conflict: set algebra combines canonical triples, and a slot is contended only
where a SHACL shape permits at most one value. Multi-valued predicates union;
divergent functional values go to a person. The same shapes graph validates
the result.

We do not claim the first three-way merge for RDF. Our contribution is an
implementation in a production multi-agent store and an evaluation against
Quit Store's Context Merge, which it extends rather than replaces, and six
other strategies.

Across five synthetic seeds, the shape-aware operator raised $33$ conflicts,
all true positives, with no triples lost or fabricated and no SHACL violations
admitted. The context-overlap baseline detected the same $33$ conflicts but
asked $845$ questions. A recorded production replay covers $105$ human alias
repairs ($93$ after excluding $12$ chained pairs) and $939$ duplicate-value
incidents. It reproduces a triple-level limit: different names for one entity
remain invisible ($0$ of $93$ alias repairs detected, matching $0$ of $21$
synthetic cases), alongside the benefit on real duplicate values.

A further synthetic study tests evolving shape contracts. Merging shape
declarations first handles the tested cardinality changes, while datatype
evolution exposes a detector blind spot caught by post-merge validation.
These results qualify schema-first orchestration rather than establish a
universal conflict-resolution rule.
\end{abstract}
