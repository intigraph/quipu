# Quipu signing primitives (source preparation)

One v1 verdict message builder, SHA-256 evidence hash, Ed25519 hex codec and
PKCS#8 host-file loader for Quipu-stack clients. Cryptography uses `ring`.
The fixed fixture was generated by the unchanged Quipu signing module;
compatibility tests check exact message and signature bytes, all six signed
fields, wrong keys and invalid encodings.

This crate is currently `publish = false`. It is an independent source package,
not admitted here as a registry dependency and not a completed consumer migration.
Quipu and Yupana still use their existing implementations until the exact shared
library distribution and publisher path is qualified and reviewed. No current
root release or consumer manifest is changed by this preparation.

The caller owns its verifier name, key path and key custody. The crate resolves
no application environment variables, registers no key and grants no trust.
Signature validity is not authorization. The loader preserves the existing v1
host-file behavior; this extraction is not a new secret store or a key-custody
hardening claim. Native key I/O is absent on Wasm; byte-based signing and
verification remain available there.

```sh
cargo test --locked --manifest-path crates/quipu-signing/Cargo.toml
cargo clippy --locked --manifest-path crates/quipu-signing/Cargo.toml --all-targets -- -D warnings
cargo check --locked --manifest-path crates/quipu-signing/Cargo.toml --target wasm32-unknown-unknown --lib
```

Run meaningful local checks under the deployment's HOME escape guard with a
private target directory. No production key or registration is needed.
